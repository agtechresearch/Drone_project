# 2026-07-09 [오후 세션] 주행 재개 성공 → 예냉실 근본원인 규명 → 재매핑 준비

## 수행 작업
1. **상태 점검**: 배터리 11.8V, AMCL (0,0,0)·move_base status 비어있음 → 초기위치 여전히 미설정, 오전 이후 실제 주행은 없었음. 라이다 실측이 오전과 동일 → 로봇 그 자리 그대로.
2. **오전 진단 정정**: 맵 원점 (0,0,0)에서 레이캐스트하니 **우측 벽 0.25m가 실측 0.26m와 일치** → 로봇은 원점 근처가 맞음. 오전의 "원점 우측 2.25m 개방"은 레이캐스트 오류였음.
3. **CLI로 `/initialpose (0,0,0)` 발행** (2D Pose Estimate의 명령어판, RViz 표준 공분산). AMCL 확정.
4. **웨이포인트 A(정면 1m) 주행 성공** — status 3 SUCCEEDED, 로봇 x=0.85 도달. `initialpose→goal→move_base→DWA→cmd_vel→모터` 전 과정 정상. **초기위치 미설정이 유일한 블로커였음이 확정.**
5. **예냉실(먼 목표) 실패** — status 4 "Failed to get a plan". costmap 0.0m clear(=live스캔 전부 제거) 후에도 실패 → **정적맵 문제**로 좁혀짐.
6. **근본원인 규명 (live global costmap BFS)**: cost≥100(실벽)만 막으면 도달 가능, cost≥99(inscribed)까지 막으면 불가. GlobalPlanner는 inscribed(99)를 장애물 취급 → 실패. **로봇이 맵상 작은 방(524셀≈1.3㎡)에 갇혀 있고, 유일 출구(~(-0.16,0.49))가 footprint inscribed(0.12m) 안에 완전히 들어갈 만큼 좁음.** 인플레이션(0.20)·costmap clear와 무관(footprint vs 맵의 좁은 길목 문제).
7. **localization 정상 확인**: 스캔을 맵에 투영 → 라이다 84%가 벽 0.15m 이내(47%<0.075m). 위치추정 OK → **맵 자체가 로봇을 가둔 것**.
8. **RViz 창 관리**: RViz가 풀스크린 UI 뒤에 깔려 안 보임 → `XRaiseWindow`로 앞으로, `XMoveResizeWindow`로 상단(1152×690)만 차지하게 축소해 하단 UI의 `RViz 닫기` 버튼 노출(터치 가능). UI는 `-fullscreen`이나 `-topmost` 아님, WM 부재로 클릭 raise 안 됨.
9. **재매핑 결정**(맵-실제 환경 차이). 자동탐사 대신 수동 텔레옵 권장(Pi CPU, 후방실명 라이다, auto_explore 회전반복 이력).
10. **새 도구 `map_teleop.sh`/`python/map_teleop.py` 제작** — 단일키 스텝 드라이버. move_direct 재사용, 노드 상주(키마다 재init 없음). i/k 전후진 0.3m, j/l 회전±30°, u/o 횡이동, r=360°스윕(후방채움), +/- 스텝, space 정지, q 종료. cbreak SSH 단일키 입력. 문법·임포트 검증 완료(대화형 tty라 로봇 실주행 첫 검증은 미완).
