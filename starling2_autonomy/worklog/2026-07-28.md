## 1. GitHub 이관

### 배치 결정

조직 저장소 `agtechresearch/Drone_project`(public, 48MB)를 조사한 결과 **드론/프로젝트별
최상위 폴더** 구조였다(`bee35_programing/`·`advancedroneprograming/`·`drone_sim/`).
우리와 성격이 같은 건 `bee35_programing/`(실기체 코드 + README + PROGRESS + 로그).

→ 컨벤션대로 **`starling2_autonomy/` 폴더 추가**로 결정. 별도 저장소 대신 이쪽을 택한 이유는
랩 드론 프로젝트를 한곳에 모으는 게 공유에 유리하고, 우리 작업이 576KB라 분리 이득이 없어서다.

트레이드오프로 감수한 것: clone 시 48MB(대부분 커밋된 동영상), 커밋 이력·태그 공유.
→ 태그는 `starling2-` 접두사, 커밋은 `[starling2]` 접두사로 구분하기로 했다.

### 워크플로 전환 — "로컬 git이 원본"

기존에는 기체 `/home/root/`가 원본이고 로컬은 "분석용 사본"이었다. 이대로 GitHub에 올리면
**기체에서 수정할 때마다 수동으로 내려받아야 하고, 한 번 까먹으면 저장소가 거짓을 기록**한다.

→ 원본을 로컬 git으로 옮겼다. `v13 → v14 → v15` 파일명 증분 관례는 사실 git이 없어서 하던
일이므로 git 이력 + 태그가 대신한다. 단 **기체에는 롤백용으로 직전 안정판(v13)을 남긴다** —
실비행 중 문제가 생기면 SSH로 파일 하나 바꾸는 게 가장 빠르다.

### PR 방식

이 저장소는 **PR 사용 이력 0건**, 전부 main 직접 push였다. 그래도 브랜치 → PR → 본인 merge
방식을 택했다. PR을 "허락받는 절차"가 아니라 **변경 내용을 설명해두는 문서**로 쓰기 위해서다.

## 2. `voa_pc_out` 파서

### 왜 직접 짰나

| 후보 | 왜 못 쓰나 |
|---|---|
| `libmodal-pipe`의 `python/pympa.py` | 66행, IMU·카메라 전용. 포인트클라우드 미지원 |
| `voxl-inspect-points` 출력 파싱 | 텍스트 요약만 나옴. 700점 × 20Hz를 텍스트로 받을 수 없음 |

→ 바이너리 FIFO 직접 read. 표준 라이브러리만 사용(numpy 불필요).

### 구현

I/O와 파싱을 분리했다 — `PointCloudStream`은 `read(n)` 콜러블만 받으므로 기체 없이 전부
테스트할 수 있고, `MpaPointCloudClient`가 실제 FIFO 구독을 담당한다.

- 와이어 포맷: packed 60바이트 헤더 `"<IqIII32sI"`, 포맷 6종 처리 (`FLOAT_XYZ`는 단일 unpack)
- 구독: `client.c` 프로토콜 그대로. 죽은 서버에 매달리지 않도록 `O_NONBLOCK` + `ENXIO` 감지,
  읽기는 `select` 타임아웃
- 방어: 매 프레임 magic 검증 + 재동기화. magic이 맞아도 `format`·`n_points` 유효성 확인
  (깨진 헤더로 수 GB 할당하는 사고 방지)
- 요약 메서드: `nearest_forward()`(전방 통로 최근접), `sector_min_x()`(방향별 최근접)
  — "앞이 막혔다"만으로는 회피 방향을 못 고르기 때문. **진단용이고 실제 정책은 별도 설계**
- 단독 실행 시 `voxl-inspect-points` 대조용 진단 CLI

### 알려진 한계 (중요)

**페이로드만 잘린 프레임은 탐지 불가.** 프로토콜에 체크섬도 프레임 구분자도 없어서, 헤더가
온전하면 파서는 `n_points`를 믿고 그만큼 읽는다. 그 프레임 하나는 다음 프레임 앞부분을
좌표로 오인하고, 다음 호출에서 재동기화로 복구된다.

다음 magic을 미리 보면 막을 수 있으나 최대 50ms 지연이 생긴다.
**회피 판단에서 그 지연이 오염 프레임 하나보다 나쁘다**고 보고 넣지 않았다.
→ **회피 로직은 단일 프레임을 신뢰하지 말 것.** 오염은 `stats["resyncs"]`로 감시.

## 주요 결론

1. **저장소 컨벤션은 폴더 추가가 맞았다.** `bee35_programing/`이 우리와 같은 성격이라 판단 근거가 명확했다.
2. **CRLF는 실제 사고 요인이었다.** `core.autocrlf=true` 환경에서 리눅스 기체용 코드를 Windows에서
   관리하면 clone하는 쪽이 깨진 파일을 받는다. `.gitattributes`가 필수였다.
3. **파서는 순수 파이썬으로 충분하다.** 성능 여유가 25배 이상이라 numpy나 `.so` 바인딩을 도입할 이유가 없다.
4. **파서의 한계는 설계 선택이었다.** 잘린 프레임 탐지는 가능하지만 50ms 지연과 맞바꿔야 해서
   포기했다. 이 결정이 회피 로직 설계에 제약을 건다(연속 프레임 판단 필수).
5. **좌표 부호 실물 검증이 최우선 미해결 항목.** 소스로 확정했을 뿐이고, 부호가 반대면
   회피가 장애물 쪽으로 간다.
