## 단계 1 — 반응형 장애물 회피 (핵심)
**하드웨어 이미 존재**: 전방 ToF(`tof`, `tof_pc`), VOA 포인트클라우드(`voa_pc_out`), 하방 rangefinder.

두 갈래 중 택1 또는 병행:

### (A) VOXL 내장 VOA 활성화 — ⛔ **막힘** (2026-07-27 조사 완료, docs/04)
- PX4 v1.14 공식 문서: Collision Prevention은 **Position 모드 전용**
  (`MPC_POS_MODE`를 0 또는 3으로 둬야 하고 기본은 4 — 기체 현재값도 4).
  **Offboard 셋포인트에는 개입하지 못한다.** → 현 구조에서 이 경로는 무효.
- `en_voa`는 이미 true이고 vision-hub가 20Hz로 `OBSTACLE_DISTANCE`를 보내는 중이지만,
  PX4가 `CP_DIST=-1`, `COM_OBS_AVOID=0`으로 전부 폐기 중.
- Position 모드 수동비행용 백스톱으로 켜두는 것은 별개로 유효.

### (B) 파이썬 레벨 반응형 회피 — ✅ **사실상 유일한 경로**
- **입력은 `voa_pc_out`을 쓴다.** 실측: Float XYZ 12B/pt, ~700pt, 20Hz.
  좌표계는 **level 프레임 = 원점이 기체, 롤/피치 제거, yaw는 기체 헤딩 유지, X전방·Y우측·Z하방.**
  이미 기체 상대 + 헤딩 정렬이라 **포즈를 읽어 변환할 필요가 없다.**
  전방 장애물 = X 큰 값 & |Y| 작은 값. (상세: docs/04)
- ⚠️ **커버리지는 ToF FOV(106.5°×85.1°, 0.15–6m) 전방 원뿔 + 하방뿐. 측·후방은 사각지대.**
  이 기체에 스테레오는 없다. 회피 정책을 이 제약 위에 설계해야 한다.
- ToF/`voa_pc_out` 파이프를 읽는 async 태스크 추가 (v13의 `voxl_pose_reader` 패턴 재사용).
- 전방 최소거리 < 임계값이면: setpoint 진행 정지(hover) → 회피 방향 재설정 → 재개.
- v13의 `setpoint_streamer`가 `self.target`만 보내므로, **회피 로직이 `self.target`을
  가로채/수정**하는 구조가 자연스러움.
- 장점: 미션 로직과 통합, 완전한 제어. 단점: 직접 구현·튜닝 필요.

## 단계 2 — 매핑 (선택)
- `voxl-mapper`/`voxl-planner` **미설치** → 설치 시 3D 점유맵 + 전역 경로계획 가능.
- 온실/실내 커버리지 자동화(현재 지그재그 하드코딩을 맵 기반 자동 생성)로 발전 가능.
- 경량 대안: ToF 포인트클라우드 누적으로 간이 점유격자 자체 구현.

## 단계 3 — 통합 자율주행
- 목표 지점만 주면 회피하며 도달 / 커버리지 자동 생성 / 실패 시 안전 복귀.
